# 风险与假设

## 1. 风险清单

| 编号 | 风险 | 类别 | 概率 | 影响 | 缓解措施 |
| --- | --- | --- | --- | --- | --- |
| RK-01 | 田径规则地域差异大（录取名次、晋级、名次分、平局规则各校不同） | 需求 | 高 | 高 | 全部规则数据化 + 三层继承（ADR-02/03）；提供规则模板导入导出（FR-EVT-15）；阶段 4 先与业务方核对默认值为「常用值」而非「唯一值」 |
| RK-02 | 全能计分表数据量大且需权威版本（男女、手计/电计、各单项） | 数据 | 中 | 高 | 独立表 `allround_score_table` + Excel 导入；内置一份常用表并在文档标注来源与「可替换」；支持手计时/电计时两套 |
| RK-03 | 自动编排算法在极端约束（场地少、项目多、兼项多）下无可行解 | 算法 | 中 | 高 | 装箱失败时返回**缺口报告**（缺几个单元/哪些项目无法安排）而非静默失败；支持局部放宽（延长单元、允许兼项间隔收紧到阈值）后再重排 |
| RK-04 | 编排性能不达标（5000 人 / 300 项目） | 性能 | 中 | 中 | 算法纯内存计算 + 批量插入（`rewriteBatchedStatements`）；冲突检测用时间区间树而非 O(n²)；阶段 5 设性能单测门禁 ≤ 10s |
| RK-05 | Excel 导入模板与用户实际表头不一致（列名、单位、成绩格式） | 可用性 | 高 | 中 | 表头模糊匹配 + 列映射界面 + 逐行错误报告（可下载）；导入前预校验不落库 |
| RK-06 | 成绩时间格式解析歧义（`11"23` / `11.23` / `1:02.45` / 手计时 0.1s 精度） | 数据 | 高 | 中 | 统一 `result_raw` + `result_value` 双列；解析器单测覆盖 ≥ 20 种写法；手/电计时精度差按规则处理（可配） |
| RK-07 | 风速与纪录认定争议（超风速是否计名次、纪录是否成立） | 规则 | 中 | 中 | 风速规则配置化；超风速标记 `is_wind_legal=false` 并可配置「名次有效但纪录不认定」；认定需人工审核（`result:record`） |
| RK-08 | 并发成绩录入导致覆盖（多个裁判同时改一组） | 并发 | 中 | 中 | `version` 乐观锁 + `clientToken` 幂等 + 审核后禁止直改；前端保存前校验版本 |
| RK-09 | PDF 中文字体缺失导致乱码 | 技术 | 中 | 中 | 字体文件内嵌进 jar/镜像（`resources/templates/fonts`）；Docker 镜像预装字体；PDF 生成加中文冒烟测试 |
| RK-10 | 局域网无外网，前端 CDN/字体图标不可用 | 部署 | 高 | 中 | 依赖本地打包（`vite build` 全量打包）、图标用 Element Plus 内置或本地 SVG、字体本地托管（ADR-09） |
| RK-11 | MySQL 8 保留字与表名冲突（`group`、`rank`、`system`） | 技术 | 低 | 中 | 表名规避（`meet_group` 等）；所有自定义 SQL 使用反引号 |
| RK-12 | 数据权限漏洞（领队看到其他单位、跨届次访问） | 安全 | 中 | 高 | MP 多租户强制 `meet_id` + Service 二次校验 + 越权集成测试门禁（P1 起每阶段回归） |
| RK-13 | 序号/号码/证书编号重复（批量生成并发） | 数据 | 低 | 中 | 编号由数据库唯一索引兜底 + 生成重试；证书编号含届次+项目+名次业务码 |
| RK-14 | 拖拽编排操作繁琐，编排员不买账（回到 Excel） | 采纳 | 中 | 高 | 支持「Excel 式表格批量编辑」与「导入外部编排结果」，不强绑拖拽；阶段 5 邀请编排员试用迭代 |
| RK-15 | 需求蔓延（大屏、门禁、直播、报名缴费等） | 项目 | 高 | 中 | 明确本期不含项（SRS 1.2）；新需求走变更评估，进入后续阶段而非插队 |
| RK-16 | 备份恢复误操作导致数据丢失 | 运维 | 低 | 高 | 恢复前自动快照 + 二次确认 + 仅 SUPER_ADMIN；恢复演练纳入阶段 10 验收 |
| RK-17 | 跨天/跨单元长跑项目（如 5000m、竞走）编排特殊 | 规则 | 中 | 中 | 项目规则含 `duration_min` 与「独占单元」标记；编排器支持独占约束 |
| RK-18 | 浏览器打印分页不可控（长表格跨页断裂） | 前端 | 中 | 中 | 打印视图专用 CSS（`break-inside: avoid`、固定表头）+ 服务端 PDF 作为正式输出通道 |

## 2. 假设

| 编号 | 假设 |
| --- | --- |
| AS-01 | 部署环境为局域网内单台 Linux/Windows 服务器，Docker 20+ 与 Docker Compose v2 可用；不要求集群/高可用。 |
| AS-02 | 参赛规模上限：单届 ≤ 5000 名运动员、≤ 300 个项目、≤ 60 个参赛单位、≤ 120 个竞赛单元。超出需重新评估性能。 |
| AS-03 | 报名数据来源为领队 Web 端录入或管理员 Excel 导入，不直接对接外部报名系统（若需要，走 Excel 中转）。 |
| AS-04 | 电子计时/测距设备不直连，通过导出文件映射导入；预留统一成绩写入 API。 |
| AS-05 | 用户能提供或认可内置的全能计分表、名次分表、纪录基线数据；如不认可，可导入替换。 |
| AS-06 | 成绩时间精度默认 1/100 秒，手计时项目按规则折算（可在系统参数与项目规则中调整）。 |
| AS-07 | 裁判岗位与人数可由业务方在「裁判岗位字典」中自行维护，系统只提供常用默认值。 |
| AS-08 | 打印以 A4 竖版为主，秩序册/成绩册可横版；黑白打印可用。 |
| AS-09 | 不需要多语言（仅简体中文）；不需要移动端原生 App，但页面需在平板/手机浏览器可用。 |
| AS-10 | 大屏在赛事现场通过浏览器全屏展示（可无人登录，用大屏 Token 访问）。 |
| AS-11 | 每阶段交付后由用户确认再进入下一阶段；确认周期内的变更进入下一阶段而非当前阶段。 |
| AS-12 | 开发环境具备 JDK 17、Maven 3.9+、Node 18+、pnpm；运行环境只需 Docker。 |

## 4. 待确认问题（进入阶段 1 前需要答复）

| 编号 | 问题 | 默认处理（若未答复） |
| --- | --- | --- |
| Q-01 | 阶段 1 是否按本设计直接开工（工程脚手架 + 系统管理）？ | 视为确认，按 P1 开工 |
| Q-02 | 是否需要「运动员自助注册/登录」角色（ATHLETE）？ | 默认保留角色但不开放注册入口 |
| Q-03 | 全能计分表与纪录数据由谁提供？ | 先用内置常用表 + 演示数据，后续导入替换 |
| Q-04 | 是否需要多语言/繁简切换？ | 默认仅简体中文 |
| Q-05 | 是否需要对接电子计时设备或现场 LED 屏？ | 默认不直连，仅文件导入 |
| Q-06 | 部署目标是 Windows 还是 Linux 服务器？ | 默认两者都支持，文档以 Linux 为主、Windows 附脚本 |
| Q-07 | 冠军/名次并列的处理偏好（并列同名次 vs 名次顺延）？ | 默认并列同名次 + 名次分均分，可在规则中改 |
| Q-08 | 是否需要手机端扫码查询成绩（二维码）？ | 默认证书带二维码，成绩查询页做响应式，不做小程序 |
