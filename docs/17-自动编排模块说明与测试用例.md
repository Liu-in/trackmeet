## 二、算法说明

### 2.1 日程自动编排 —— `SchedulePacker.pack(sessions, tasks, options)`

**输入**：`SessionSpec[]`（单元：日期/时段/起止时刻/主场地/可用田赛场地）、`ScheduleTask[]`（项目×轮次：人数/组数/预计时长/优先级/时段偏好/锁定信息/参赛运动员）、`ScheduleOptions`（兼项间隔、同项目轮次最小间隔、田赛并行开关与场地数上限）。
**输出**：`SchedulePlan`（排定条目 + 缺口报告 + 冲突清单 + 已排/未排计数）。

| 步骤 | 处理 |
| --- | --- |
| 1 | **锁定条目先占位**：`locked=true` 且带 `lockedStart` 的条目直接进入结果，占用跑道/场地游标与运动员时间，后续不移动 |
| 2 | **会话排序**：日期 → 时段（上午/下午/晚上）→ 开始时刻 |
| 3 | **任务排序**：优先级 → 径赛优先 → 人数多者优先 → 项目 ID |
| 4 | **场地时间轴**：径赛串行占用主场地（跑道游标）；田赛按场地分别维护游标并可并行（并行场地数受 `maxFieldVenues` 限制，选择「游标最早」的场地做负载均衡） |
| 5 | **运动员约束**：新条目的 `[start, end]` 既不与同一运动员的已排条目重叠，又需满足兼项最小间隔；不满足时向后推进并重新校验（最多 50 次试探） |
| 6 | **轮次间隔**：同项目相邻轮次之间至少间隔 `minGapMin` 分钟 |
| 7 | **时段偏好**：先尝试偏好时段；全部放不下时退化为任意时段再试一轮 |
| 8 | **缺口报告**：所有单元都放不下的项目汇总为 `shortageMessages`，并给出「增加单元/延长时长/增加场地/下调时长」建议 |
| 9 | **冲突检测**：对排定结果调用 `ConflictDetector` 输出冲突清单 |

**复杂度**：任务数 T、单元数 S；单任务试探上限 50，运动员推进上限 100 → `O(T · S · 50 · 100 · A)`（A 为单项目运动员数），实测数据规模（300 项目 / 120 单元）在毫秒级。

### 2.2 径赛分组 —— `SerpentineGrouper.group(entries, options)`

| 步骤 | 处理 |
| --- | --- |
| 1 | **排序**：有种子成绩者按成绩（径赛越小越好 / 田赛越大越好，由 `seedAscending` 控制）；无成绩者按号码（或按 `randomSeed` 随机）排在最后 |
| 2 | **组数**：`heatCount` 优先；否则 `ceil(人数 / heatSize)`；上限为人数 |
| 3 | **蛇形（S 型）分配**：第 1 轮按键号正序放入各组，第 2 轮逆序，交替进行 → 各组实力均衡且人数自动差 ≤ 1 |
| 4 | **同单位避开**：对组内单位重复的成员，与其它组中「换入本组不新增重复、换出对方组也不新增重复」的成员交换，最多 3 轮修复（避免死循环） |
| 5 | **人数均衡**：最多组与最少组相差 > 1 时转移一名成员（优先选择不破坏单位分散者），带 1000 次上限保护 |

**输出**：`HeatResult[]`，组号从 1 开始，**组内顺序即道次优先级**。

### 2.3 道次分配 —— `LaneAllocator.assign(members, options)`

- 默认道次顺序：**8 道 `4,5,3,6,2,7,1,8`**；**6 道 `3,4,2,5,1,6`**；4 道 `3,4,2,1`；9/10 道在 8 道顺序后追加外侧道次。
- 顺序来源优先取项目级规则 `event_rule_config.lane_order_json`，其次场地 `venue.lane_order_json`，最后默认值。
- 分配方式：`SEED`（按成绩顺序，最优成绩占最优道次）、`ORDER`（输入顺序）、`DRAW`（抽签，`randomSeed` 可复现）、`SERPENT`（折半交错 1、n/2+1、2、n/2+2…，用于合并两个来源半场的选手）。
- 健壮性：道次顺序覆盖不足时按编号升序补齐；成员多于道次时仅前 `laneCount` 名获得道次（其余为替补）；道次不重复。

### 2.4 田赛出场顺序 —— `FieldOrderGenerator.generate(entries, mode, seedAscending, randomSeed)`

- `RANDOM` 随机抽签（可复现）、`SEED` 按报名成绩（缺失者排最后并按号码兜底）、`UNIT` 按单位顺序、`BIB` 按号码顺序。
- 结果列表顺序即出场顺序，落库到 `field_order.order_no`。

### 2.5 冲突检测 —— `ConflictDetector.detect(items, options)`

| 类型 | 触发条件 | 级别 |
| --- | --- | --- |
| `VENUE` 场地冲突 | 同场地 + 时间重叠 | ERROR |
| `ATHLETE` 兼项冲突 | 同运动员 + 时间重叠 | ERROR |
| `REFEREE` 裁判冲突 | 同裁判 + 时间重叠 | ERROR |
| `INTERVAL` 间隔不足 | 不重叠但同运动员间隔 < `athleteIntervalMin` 或同裁判间隔 < `refereeIntervalMin` | WARN |

输出字段含 `conflictType / level / scheduleId / relatedScheduleId / athleteId / refereeId / venueId / overlapMinutes / intervalMinutes / requiredIntervalMin / message`（中文可读），并按「ERROR 优先 → 日程 ID」排序。

### 2.6 时长估算 —— `DurationEstimator.estimate(eventType, subType, participantCount, heatCount, attemptCount)`

- 径赛：`每组分钟数 × 组数 + 5`（短跑 6、跨栏 8、中跑 10、长跑/障碍 18、竞走 20、接力 8）；
- 田赛：`ceil(人数 × 试跳次数 × 1.2)`，限制在 `[15, 150]` 分钟；
- 全能：整段 180 分钟；
- 全部为「兜底默认」，业务上以 `event_schedule_rule.default_duration_min` 与 `event.duration_min` 为准。

## 五、联调步骤（curl）

```bash
BASE=http://localhost:8080/api
TOKEN=$(curl -s -X POST $BASE/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')
AUTH="Authorization: Bearer $TOKEN"; MEET="X-Meet-Id: 1"

# ① 场地与竞赛单元（自动编排的输入）
curl -s "$BASE/venues?meetId=1" -H "$AUTH" -H "$MEET"
curl -s -X POST "$BASE/sessions" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"meetId":1,"sessionName":"第一天上午","sessionDate":"2025-10-18","period":"MORNING",
       "startTime":"08:00:00","endTime":"12:00:00","venueId":1}'

# ② 自动编排：先预览（不落库）
curl -s -X POST "$BASE/schedule/auto" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"meetId":1,"scope":"ALL","keepLocked":true,"athleteIntervalMin":30,"apply":false}'
# ③ 确认后落库
curl -s -X POST "$BASE/schedule/auto" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"meetId":1,"scope":"ALL","keepLocked":true,"athleteIntervalMin":30,"apply":true}'
# ④ 日程查询与冲突检测
curl -s "$BASE/schedule?meetId=1&page=1&size=50" -H "$AUTH" -H "$MEET"
curl -s -X POST "$BASE/schedule/conflicts/detect" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' -d '{"meetId":1}'

# ⑤ 分组分道（对某条日程）
curl -s -X POST "$BASE/heats/generate" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"scheduleId":1,"drawMode":"SERPENT","avoidSameUnit":true,"laneMode":"SEED","apply":true}'
curl -s "$BASE/heats?scheduleId=1" -H "$AUTH" -H "$MEET"
curl -s -X POST "$BASE/lanes/assign" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"heatIds":[1,2],"mode":"SEED"}'

# ⑥ 田赛顺序
curl -s -X POST "$BASE/field-orders/generate" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"scheduleId":5,"mode":"SEED","apply":true}'

# ⑦ 拖拽调整与锁定
curl -s -X PUT  "$BASE/schedule/1/lock" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' -d '{"locked":true}'
curl -s -X POST "$BASE/schedule/2/move" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"sessionId":2,"startTime":"2025-10-18 14:30:00","venueId":1,"adjustReason":"拖拽调整"}'
curl -s -X PUT  "$BASE/schedule/1/publish" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' -d '{"publishStatus":"PUBLISHED"}'

# ⑧ 秩序册与检录表
curl -s "$BASE/print/order-book/schedule?meetId=1&publishOnly=true" -H "$AUTH" -H "$MEET"
curl -s "$BASE/print/calling-sheets?meetId=1" -H "$AUTH" -H "$MEET"
curl -s -o 秩序册.xlsx "$BASE/print/order-book/export?meetId=1&format=xlsx" -H "$AUTH" -H "$MEET"
```

| 用例 | 步骤 | 预期结果 |

## 八、已知边界

1. **编排算法为启发式装箱**：追求「可用解 + 缺口报告」，不保证全局最优；极端约束（场地极少、兼项极多）下会给出未排项目与调整建议。
2. 裁判冲突检测依赖 `referee_assignment` 数据；裁判分工模块（阶段 4）交付前，`ScheduledItem.refereeIds` 为空，裁判类冲突不会被触发。
3. 秩序册输出提供 **Excel + A4 网页打印（浏览器另存为 PDF）** 双通道；服务端 PDF 需内嵌中文字体，留待后续阶段（内网无字体文件时不硬编码）。
4. 编排结果的时间精度为分钟；径赛成绩精度（1/100 秒）在成绩模块处理。
5. 快照回滚会覆盖当前日程，恢复前请先手动保存一次快照。
