# 开发里程碑

> 相对周期以「阶段 1 开工」为第 1 周（W1）。每阶段以「可运行的闭环」为交付单元，先设计确认后编码。
> 人力假设：1 名全栈开发（可按阶段增补前端/测试并行，里程碑不变，周期压缩约 30%）。

## 3. 关键路径与并行建议

```
P0 设计 ──▶ P1 脚手架(系统管理) ──▶ P2 基础数据 ──┬──▶ P3 报名 ──┐
                                                  │              ├──▶ P5 编排 ★关键路径 ──┬──▶ P6 赛前+秩序册 ──▶ P9 打印大屏 ──▶ P10 验收
                                                  └──▶ P4 规则 ──┘                        └──▶ P7 成绩 ──▶ P8 积分 ──┘
```
- **关键路径**：P1 → P2 → (P3∥P4) → **P5** → P7 → P8 → P9 → P10。P5 编排是风险与工期双高峰。
- **可并行**：
  - P3（报名）与 P4（规则）互不依赖，可双人并行。
  - P6（赛前+秩序册）与 P7（成绩）在 P5 完成后可并行；但两者共用 `result`/`calling` 衔接字段，接口契约需在 P5 结束时冻结。
  - 打印视图（P9 的 12 个 A4 页面）在数据接口稳定后可提前开发，不阻塞主链路。
- **建议冻结点**：
  | 冻结点 | 时点 | 内容 |
  | --- | --- | --- |
  | F1 | M1 结束 | 统一返回格式、错误码、鉴权与数据权限机制冻结 |
  | F2 | M2 结束 | 数据库表结构与字段冻结（后续仅允许加列，不改语义） |
  | F3 | M3 结束 | 编排结果数据结构（schedule/heat/lane/field_order）冻结 |
  | F4 | M4 结束 | 成绩与晋级接口契约冻结，打印与大屏只读消费 |
  | F5 | M5 结束 | 报表模板与打印版式冻结，进入验收 |

## 4. 里程碑风险缓冲

| 里程碑 | 主要风险 | 缓冲策略 |
| --- | --- | --- |
| M1 | 环境差异（Docker/时区/字符集）导致启动失败 | 提供一键脚本 + 健康检查 + FAQ；先用 MySQL 容器验证全流程 |
| M2 | 导入模板与真实表头不一致 | 做列映射与模糊匹配；预留 1 天对接调整模板 |
| M3 | 编排算法在极端约束下无解或超时 | 预留 2 天专项优化；先保「可用解 + 缺口报告」，再迭代最优解 |
| M4 | 规程差异导致晋级/录取规则调整 | 规则全部配置化，调整仅改数据不改代码；预留 1 天回归 |
| M5 | PDF 中文/分页问题 | 字体内嵌 + 打印冒烟测试纳入 CI；服务端 PDF 与前端打印双通道互备 |
| M6 | UAT 期发现成绩口径错误 | 积分与名次支持「一键重算」，修正数据后无需人工修表 |
