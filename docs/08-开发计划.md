# 开发计划

> 原则：**每阶段只交付一个可运行的最小闭环**，先设计 → 确认 → 编码；每阶段固定输出「目标 / 文件树 / 完整代码 / SQL / 运行命令 / 测试方法 / 下一阶段建议」。
> 工作量估算为单名全栈开发者投入的「人日」，团队并行时可压缩。

## 2. 各阶段详细说明

### P0 设计基线（本阶段）
- **目标**：确认范围、数据模型、接口契约、页面清单与实施路径，降低后期返工。
- **交付**：`docs/00`–`docs/09`。
- **验收**：用户确认 9 项产出；无阻塞性「待确认问题」（见风险文档第 4 节）。

### P1 工程脚手架 + 系统管理
- **目标**：`docker compose up -d` 后可访问登录页，用默认账号登录，看到按权限生成的菜单。
- **文件树**：`backend/` 骨架（common/config/security/modules/system）、`frontend/` 骨架（layout/router/store/api）、`deploy/`、`sql/01-schema.sql`（系统 16 张表）、`sql/02-init-data.sql`。
- **关键任务**
  1. Maven + Spring Boot 3 + MP + JWT + 全局异常 + 统一返回 `R<T>`。
  2. `sys_*` 16 张表 DDL、MP 多租户/逻辑删除/乐观锁/分页插件。
  3. 登录/登出/刷新/验证码/个人中心；RBAC 动态菜单与按钮权限。
  4. 用户/角色/菜单/部门/字典/操作日志/登录日志/系统参数/备份。
  5. 前端：Axios 封装（统一 code 处理）、动态路由、`v-perm`、ProTable 雏形、字典组件。
  6. Docker Compose（MySQL + backend + nginx 前端）、初始化 SQL 自动执行。
- **验收**：登录成功、菜单按角色显示、越权接口返回 403、操作日志有记录、`docker compose up` 一键可用。
- **测试**：`AuthApiIT`（登录/错误密码/令牌失效）、`PermissionIT`（按钮权限拦截）、前端登录与菜单渲染冒烟。

### P2 届次基础数据
- **目标**：能创建一届完整运动会的基础数据（组别、单位、场地、裁判），并复制模板。
- **交付**：`meet/meet_group/unit/unit_staff/venue/venue_slot/referee/meet_rule_config/meet_clone_log`，页面 #3–#8。
- **验收**：创建运动会 → 复制模板 → 复制后组别/单位/项目/规则一致；场地道数可配 8/6。
- **测试**：`MeetServiceTest`（状态机流转、复制范围）、`VenueRuleTest`（道数校验）。

### P3 运动员与报名
- **目标**：领队可在线报名、管理员可导入与审核，限制校验全部生效。
- **交付**：`athlete/registration/relay_member/registration_limit/athlete_event_count`，页面 #9–#13，Excel 模板与错误报告。
- **验收**：超项/超人数/重复报名/组别错误全部拦截并给出可读原因；批量导入 500 行 ≤ 10s 且错误行可下载。
- **测试**：`RegistrationLimitTest`（边界：恰好达上限）、`AthleteImportTest`（脏数据/重复证件号）、`RegistrationApiIT`。

### P4 项目与规则配置
- **目标**：全部田径规则可配置、可继承、可覆盖、可导出复用。
- **交付**：`event/event_round/event_round_rule/event_rule_config/score_rule(+item)/bonus_rule/allround_event/allround_score_table/event_schedule_rule`，页面 #14–#18。
- **验收**：三层继承生效（改届次默认 → 未覆盖的项目随之变化；项目覆盖后不受届次影响）；恢复继承可用。
- **测试**：`RuleResolverTest`（继承链、恢复继承）、`AllroundScoreLookupTest`（查表边界值）、`ScoreRuleTiePolicyTest`。

### P5 编排引擎（最关键阶段）
- **目标**：一键生成可用日程 + 分组 + 道次 + 田赛顺序，四类冲突可检测，全部结果可拖拽/锁定/重生成。
- **交付**：`engine/grouping|lane|fieldorder|schedule|conflict`、`schedule_session/schedule/heat/heat_member/lane/field_order/conflict_log/schedule_snapshot`，页面 #19–#22。
- **验收**
  1. 300 个项目 / 5000 运动员自动编排 ≤ 10s（NFR-02）。
  2. 分组人数差 ≤ 1；同单位在同组人数 ≤ 规则上限；蛇形分布正确。
  3. 道次严格按配置顺序（8 道 `4,5,3,6,2,7,1,8`；6 道 `3,4,2,5,1,6`）分配。
  4. 锁定条目在重新生成后位置与分组不变。
  5. 四类冲突全部可检出并可通过 `PUT /conflicts/{id}/resolve` 处理。
- **测试**：算法单测覆盖全部分支（含人数为 0/1、报名成绩缺失、场地不足、时间不足等异常场景）+ 编排幂等性测试 + 拖拽后一致性测试。

### P6 赛前管理 + 秩序册
- **目标**：秩序册可打印发布；检录可执行；裁判分工可下发。
- **交付**：`calling/draw_record/start_list/referee_duty/referee_assignment`，页面 #23–#27 与打印视图 P1/P4/P5/P12。
- **验收**：秩序册 PDF 分页正确、A4 无内容截断；检录状态可批量登记并同步到成绩录入。
- **测试**：`DrawingSheetPdfTest`（PDF 生成与页数）、`CallingFlowIT`（检录 → 成绩录入联动）。

### P7 成绩管理
- **目标**：成绩从录入到审核、留痕、晋级、破纪录形成闭环。
- **交付**：`result/result_attempt/wind_reading/result_audit/advance_result/record`，页面 #28–#32、#34（纪录）。
- **验收**：径赛/田赛/全能三类录入均可；DNS/DNF/DSQ/NM 处理正确；超风速（> +2.0 m/s）自动标记且纪录不认定；已审核成绩禁止直改；晋级「每组前 N + 剩余最好成绩递补」结果与人工核对一致。
- **测试**：`AdvanceCalculatorTest`（并列边界、递补不足）、`WindValidateTest`、`ResultAuditTest`（前后值留痕）、`ResultEntryApiIT`（并发提交幂等）。

### P8 统计与积分
- **目标**：一键生成名次、积分、团体总分、奖牌榜、证书。
- **交付**：`score 计算引擎`、`points/team_score/medal_standing/certificate`，页面 #33–#36、打印视图 P6/P7/P8。
- **验收**：名次分、破纪录加分、接力双倍分计算与手工核算一致；并列名次按 `tie_policy` 正确；奖牌榜排序符合配置。
- **测试**：`RankPointCalculatorTest`（含并列均分/满额）、`BonusCalculatorTest`（多层级叠加开关）、`TeamScoreAggregateTest`。

### P9 打印导出 + 大屏公告
- **目标**：全量报表可导出 PDF/Excel/Word/CSV；大屏与公告可用。
- **交付**：打印中心、模板配置、剩余打印视图（P2/P3/P9/P10/P11）、`announcement/print_template/screen_config`，页面 #37–#38、#48、S1–S4。
- **验收**：12 类报表 × 4 种格式全部可用；模板改动即时生效；大屏 15s 自动刷新、断网保留最后数据。
- **测试**：`PrintCenterIT`（各报表各格式 200 + 文件非空）、`ScreenDataIT`（聚合数据与榜单一致）。

### P10 部署加固 + 验收
- **目标**：局域网生产环境稳定运行，可备份恢复，完成 UAT。
- **交付**：`deploy/scripts/*`、压测报告、验收用例与用户手册。
- **验收**：`docker compose` 一键启动；备份 → 清库 → 恢复 数据完整；50 并发下 P95 < 1s；UAT 用例 100% 通过。
- **测试**：JMeter/`autocannon` 压测脚本、备份恢复演练脚本、全流程端到端（报名 → 编排 → 比赛 → 成绩 → 积分 → 打印）。

## 4. 交付规范（每阶段统一格式）

1. **本阶段目标**：范围与验收标准。
2. **文件树**：新增/修改文件列表。
3. **完整代码**：可直接运行，不含伪代码与 TODO 占位（若必须分期，明确标注）。
4. **SQL**：本阶段新增的表与初始化数据。
5. **运行命令**：本地开发与 Docker 两种方式。
6. **测试方法**：单测/集成测试命令与手工验证步骤。
7. **下一阶段建议**：范围与前置依赖。

## 5. 质量门禁

| 门禁 | 标准 |
| --- | --- |
| 编译 | 后端 `mvn -q clean test` 通过；前端 `pnpm build` 无 TS 错误 |
| 测试 | 核心算法类行覆盖率 ≥ 80%；关键接口具备集成测试 |
| 规范 | 统一返回格式、统一错误码、无硬编码规则常量 |
| 日志 | 关键写操作有操作日志，成绩/规则/编排有业务留痕 |
| 安全 | 越权用例（跨届次、跨单位）必须返回 403 |
