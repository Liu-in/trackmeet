## 第 2 节 届次基础层

### meet 运动会（届次）表
> 一届运动会的根实体，是所有业务数据的隔离边界与全局开关。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `meet_name` | VARCHAR(100) | 运动会名称 |
| `edition` | VARCHAR(50) | 届次标识（如「2025年第19届」） |
| `short_name` | VARCHAR(50) | 简称（大屏、证书使用） |
| `host` | VARCHAR(100) | 主办单位 |
| `organizer` | VARCHAR(100) | 承办单位 |
| `co_organizer` | VARCHAR(100) | 协办单位 |
| `start_date` | DATE | 比赛开始日期 |
| `end_date` | DATE | 比赛结束日期 |
| `place` | VARCHAR(100) | 举办地点 |
| `reg_start_time` | DATETIME | 报名开始时间 |
| `reg_end_time` | DATETIME | 报名截止时间 |
| `status` | VARCHAR(32) | 届次状态（八态，取值见下） |
| `regulation_html` | LONGTEXT | 竞赛规程 HTML |
| `regulation_file_id` | BIGINT UNSIGNED | 规程附件 `sys_file.id` |
| `logo_file_id` | BIGINT UNSIGNED | 会徽附件 `sys_file.id` |
| `is_template` | TINYINT(1) | 是否可作为复制模板 |
| `config_json` | JSON | 届次默认规则扩展（详见 `meet_rule_config`） |
| `remark` | VARCHAR(100) | 备注 |

**枚举取值**：`status` = `DRAFT` 草稿 / `REG_OPEN` 报名中 / `REG_CLOSED` 报名截止 / `SCHEDULING` 编排中 / `SCHEDULED` 编排完成 / `RUNNING` 比赛进行 / `FINISHED` 已结束 / `ARCHIVED` 归档。

**索引与约束**：`UK(meet_name, edition)`、`IDX(status)`、`IDX(start_date)`

### meet_group 组别表
> 划分参赛对象（性别、年龄、年级），并决定是否计入团体分与使用哪套组别纪录。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `group_name` | VARCHAR(100) | 组别名称（如高中男子组） |
| `group_code` | VARCHAR(64) | 组别编码（届次内唯一） |
| `gender` | VARCHAR(32) | 性别限制：`MALE` 男 / `FEMALE` 女 / `MIXED` 混合 |
| `age_min` | SMALLINT | 最小年龄（含） |
| `age_max` | SMALLINT | 最大年龄（含） |
| `birth_date_start` | DATE | 出生日期区间起（资格判定基准） |
| `birth_date_end` | DATE | 出生日期区间止 |
| `grade_range` | VARCHAR(100) | 年级范围（如高一至高三） |
| `is_team_score` | TINYINT(1) | 是否计入团体总分 |
| `score_group_code` | VARCHAR(64) | 团体计分归并码（跨组合并计分） |
| `record_group_code` | VARCHAR(64) | 组别纪录归并码（对应 `record`） |
| `sort_no` | SMALLINT | 显示排序号 |
| `status` | VARCHAR(32) | 状态：`ENABLED` 启用 / `DISABLED` 停用 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`UK(meet_id, group_code)`、`IDX(meet_id, sort_no)`、`IDX(meet_id, gender)`

### unit 参赛单位表
> 参赛主体的组织单元，承载号码布前缀、领队教练归属与单位级报名上限。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `unit_name` | VARCHAR(100) | 单位名称 |
| `unit_code` | VARCHAR(64) | 单位编码（届次内唯一） |
| `short_name` | VARCHAR(50) | 单位简称（榜单、大屏） |
| `unit_type` | VARCHAR(32) | 类型：`SCHOOL` 学校 / `CLUB` 俱乐部 / `OTHER` 其他 |
| `number_prefix` | VARCHAR(50) | 号码布前缀（如「一中」） |
| `leader` | VARCHAR(50) | 领队姓名（主联系人） |
| `coach` | VARCHAR(50) | 主教练姓名 |
| `phone` | VARCHAR(50) | 联系电话 |
| `address` | VARCHAR(100) | 通信地址 |
| `logo_file_id` | BIGINT UNSIGNED | 单位标志附件 `sys_file.id` |
| `group_scope_json` | JSON | 可参加的组别范围（组别编码数组） |
| `total_quota` | INT | 单位报名人数上限（0 表示不限） |
| `status` | VARCHAR(32) | 状态：`ENABLED` 启用 / `DISABLED` 停用 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`UK(meet_id, unit_code)`、`IDX(meet_id, status)`

### unit_staff 单位领队/教练表
> 记录各单位领队、教练、队医等随队人员，用于数据权限关联与秩序册编制。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `unit_id` | BIGINT UNSIGNED | 所属单位 `unit.id` |
| `staff_name` | VARCHAR(50) | 姓名 |
| `staff_type` | VARCHAR(32) | 类型：`LEADER` 领队 / `COACH` 教练 / `DOCTOR` 队医 |
| `gender` | VARCHAR(32) | 性别：`MALE` 男 / `FEMALE` 女 |
| `phone` | VARCHAR(50) | 联系电话 |
| `id_card` | VARCHAR(32) | 身份证号（兼容护照号） |
| `duty_title` | VARCHAR(50) | 职务/职称 |
| `is_contact` | TINYINT(1) | 是否单位唯一联系人 |
| `sort_no` | SMALLINT | 显示排序号 |
| `status` | VARCHAR(32) | 状态：`ENABLED` 启用 / `DISABLED` 停用 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`IDX(unit_id, staff_type)`、`UK(meet_id, unit_id, id_card)`

### venue 场地表
> 比赛场地及其道数与道次顺序配置，是径赛道次分配算法的输入。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `venue_name` | VARCHAR(100) | 场地名称 |
| `venue_code` | VARCHAR(64) | 场地编码（届次内唯一） |
| `venue_type` | VARCHAR(32) | 类型：`TRACK` 径赛 / `FIELD` 田赛 / `INDOOR` 馆内 |
| `lane_count` | SMALLINT | 道数（6 道或 8 道） |
| `lane_order_json` | JSON | 道次优先顺序，默认 8 道 `[4,5,3,6,2,7,1,8]` |
| `lane_width` | DECIMAL(10,2) | 单道宽度（米） |
| `location` | VARCHAR(100) | 场地位置描述 |
| `capacity` | INT | 可容纳观众人数 |
| `is_wind_measured` | TINYINT(1) | 是否配置风速测量设备 |
| `is_electric_timing` | TINYINT(1) | 是否具备电子计时 |
| `field_zone_json` | JSON | 田赛区配置（跳跃区、投掷区编号与朝向） |
| `available_json` | JSON | 可用情况扩展（可承接项目类型、限制说明） |
| `contact_name` | VARCHAR(50) | 场地联系人 |
| `contact_phone` | VARCHAR(50) | 联系人电话 |
| `status` | VARCHAR(32) | 状态：`ENABLED` 启用 / `DISABLED` 停用 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`UK(meet_id, venue_code)`、`IDX(meet_id, venue_type)`

### venue_slot 场地可用时段表
> 把场地按日期与时刻切成可排期时段，供自动编排与场地冲突检测使用。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `venue_id` | BIGINT UNSIGNED | 场地 `venue.id` |
| `slot_date` | DATE | 时段日期 |
| `day_no` | SMALLINT | 比赛日序号（第 1、2 个比赛日） |
| `start_time` | TIME | 时段开始时刻 |
| `end_time` | TIME | 时段结束时刻 |
| `session_id` | BIGINT UNSIGNED | 关联竞赛单元 `schedule_session.id` |
| `slot_type` | VARCHAR(32) | 时段类型：`COMPETITION` 比赛 / `WARMUP` 热身 / `MAINTENANCE` 维护 |
| `lane_scope_json` | JSON | 本时段可用道次范围，如 `[1,2,3,4,5,6,7,8]` |
| `capacity` | INT | 本时段可同时容纳的项目数 |
| `is_available` | TINYINT(1) | 是否可用 |
| `unavailable_reason` | VARCHAR(100) | 不可用原因 |
| `sort_no` | SMALLINT | 显示排序号 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`IDX(venue_id, slot_date)`、`IDX(meet_id, slot_date, start_time)`、`UK(venue_id, slot_date, start_time, slot_type)`

### referee 裁判/工作人员表
> 裁判与工作人员档案，含岗位类型、等级与每日可承担岗位数，是分工与冲突检测的主体。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `referee_name` | VARCHAR(50) | 姓名 |
| `gender` | VARCHAR(32) | 性别：`MALE` 男 / `FEMALE` 女 |
| `unit_id` | BIGINT UNSIGNED | 所属单位 `unit.id`（外聘可空） |
| `unit_name` | VARCHAR(100) | 所属单位名称（外部人员直接填写） |
| `duty_type` | VARCHAR(32) | 主岗位类型：`TRACK` 径赛 / `FIELD` 田赛 / `RECORD` 记录 / `OTHER` 其他 |
| `referee_level` | VARCHAR(50) | 裁判等级（国家级、一级、二级） |
| `phone` | VARCHAR(50) | 联系电话 |
| `id_card` | VARCHAR(32) | 身份证号（兼容护照号） |
| `cert_no` | VARCHAR(64) | 裁判证书编号 |
| `is_chief` | TINYINT(1) | 是否具备裁判长资格 |
| `is_external` | TINYINT(1) | 是否外聘人员 |
| `max_duty_per_day` | SMALLINT | 单日最多承担岗位数（分工约束） |
| `available_json` | JSON | 可工作时间与偏好岗位 |
| `status` | VARCHAR(32) | 状态：`ENABLED` 启用 / `DISABLED` 停用 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`IDX(meet_id, duty_type)`、`IDX(meet_id, unit_id)`、`UK(meet_id, id_card)`

### referee_assignment 裁判分工表
> 按日程/单元给裁判分派具体岗位与起止时段，为裁判时间冲突检测提供数据。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `referee_id` | BIGINT UNSIGNED | 裁判 `referee.id` |
| `schedule_id` | BIGINT UNSIGNED | 日程条目 `schedule.id` |
| `session_id` | BIGINT UNSIGNED | 竞赛单元 `schedule_session.id` |
| `event_id` | BIGINT UNSIGNED | 关联项目 `event.id` |
| `round_id` | BIGINT UNSIGNED | 关联轮次 `event_round.id` |
| `venue_id` | BIGINT UNSIGNED | 执行场地 `venue.id` |
| `duty_code` | VARCHAR(32) | 岗位编码（对应 `referee_duty.duty_code`） |
| `post_no` | SMALLINT | 岗位序号（第几道、第几组、第几号位） |
| `duty_role` | VARCHAR(32) | 岗位角色：`MAIN` 主岗 / `ASSIST` 副岗 |
| `start_time` | DATETIME | 分工开始时间（含提前到场） |
| `end_time` | DATETIME | 分工结束时间 |
| `assign_mode` | VARCHAR(32) | 分配方式：`AUTO` 自动 / `MANUAL` 手动 |
| `is_chief` | TINYINT(1) | 是否本场主裁 |
| `conflict_flag` | TINYINT(1) | 是否检测到时间冲突 |
| `status` | VARCHAR(32) | 状态：`PLANNED` 待执行 / `CONFIRMED` 已确认 / `FINISHED` 已完成 / `CANCELLED` 已取消 |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`UK(schedule_id, referee_id, duty_code)`、`IDX(referee_id, session_id)`、`IDX(meet_id, start_time, end_time)`、`IDX(schedule_id, status)`

### record 纪录表
> 多层级纪录库（世界到组别），支持风速与是否现行标记，供成绩实时对标。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `record_type` | VARCHAR(32) | 纪录层级（七层级，取值见下） |
| `event_id` | BIGINT UNSIGNED | 关联项目 `event.id` |
| `event_name` | VARCHAR(100) | 项目名称（冗余显示） |
| `group_id` | BIGINT UNSIGNED | 关联组别 `meet_group.id`（组别纪录使用） |
| `group_code` | VARCHAR(64) | 组别归并码（对应 `meet_group.record_group_code`） |
| `gender` | VARCHAR(32) | 性别：`MALE` 男 / `FEMALE` 女 / `MIXED` 混合 |
| `is_relay` | TINYINT(1) | 是否接力项目纪录 |
| `athlete_name` | VARCHAR(50) | 纪录保持者姓名 |
| `unit_name` | VARCHAR(100) | 保持者单位/代表队 |
| `region_name` | VARCHAR(100) | 国家或地区（世界、亚洲、全国纪录） |
| `record_value` | DECIMAL(10,2) | 纪录数值（秒、米，用于排序比较） |
| `record_raw` | VARCHAR(16) | 纪录原文（显示，如 `1:02.45`） |
| `record_unit` | VARCHAR(32) | 单位：`s` 秒 / `m` 米 / `cm` 厘米 / `pt` 分 |
| `wind_speed` | DECIMAL(10,2) | 创造时风速（米/秒，正值顺风） |
| `is_wind_legal` | TINYINT(1) | 风速是否合规 |
| `record_date` | DATE | 创造日期 |
| `record_place` | VARCHAR(100) | 创造地点 |
| `is_current` | TINYINT(1) | 是否现行纪录（0 为历史纪录） |
| `source` | VARCHAR(100) | 数据来源（协会公布、组委会认定） |

**枚举取值**：`record_type` = `WORLD` 世界 / `ASIA` 亚洲 / `NATION` 全国 / `PROVINCE` 省 / `CITY` 市 / `MEET` 赛会 / `GROUP` 组别。

**索引与约束**：`IDX(meet_id, event_id, record_type)`、`IDX(meet_id, event_id, group_code, gender, is_current)`、`IDX(meet_id, is_current)`

### meet_rule_config 届次级规则表
> 届次默认规则的结构化落点，作为「届次 → 项目 → 轮次」三层继承的最上层；项目级覆盖见 `event_rule_config`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `admit_rank` | SMALLINT | 默认录取名次（如 8 取前 8 名） |
| `score_rule_id` | BIGINT UNSIGNED | 默认名次分方案 `score_rule.id` |
| `athlete_max_events` | SMALLINT | 每人限报项数（0 表示不限） |
| `relay_max_per_athlete` | SMALLINT | 每人限报接力项数 |
| `max_per_unit` | SMALLINT | 每单位每项限报人数 |
| `max_athlete_per_unit` | INT | 每单位报名总人数上限 |
| `conflict_interval_min` | SMALLINT | 兼项最小间隔分钟数（冲突检测阈值） |
| `referee_interval_min` | SMALLINT | 裁判连场最小间隔分钟数 |
| `relay_double_factor` | DECIMAL(10,2) | 接力得分双倍系数（默认 2.00） |
| `bonus_in_team_score` | TINYINT(1) | 破纪录加分是否计入团体分：1 计入 / 0 不计入 |
| `medal_sort` | VARCHAR(64) | 奖牌榜排序：`GOLD_FIRST` 金牌优先 / `TOTAL_FIRST` 奖牌总数优先 / `POINT_FIRST` 积分优先 |
| `time_precision` | VARCHAR(32) | 计时精度：`HUNDREDTH` 百分秒 / `TENTH` 十分秒 / `SECOND` 秒 |
| `field_attempt_count` | SMALLINT | 田赛默认试跳/试掷次数（如 3 次） |
| `default_lane_count` | SMALLINT | 默认道数（6 或 8） |
| `default_lane_order_json` | JSON | 默认道次顺序，8 道为 `[4,5,3,6,2,7,1,8]` |
| `lane_assign_mode` | VARCHAR(32) | 默认道次分配方式：`SEED` 按种子 / `DRAW` 抽签 / `SERPENT` 蛇形 |
| `wind_json` | JSON | 风速上限规则（各项目风速上限与超风速处理） |
| `tie_break_json` | JSON | 默认平局规则（比较次优成绩、名次并列、抽签等顺序） |
| `extra_json` | JSON | 届次规则扩展项（未结构化的默认值） |
| `remark` | VARCHAR(100) | 备注 |

**索引与约束**：`UK(meet_id)`（每届次一行默认规则）

### meet_clone_log 复制运动会留痕表
> 记录「按模板复制新一届」的范围、结果与耗时，便于追溯与失败重试。

| `source_meet_name` | VARCHAR(100) | 源届次名称（冗余显示） |
| `target_meet_id` | BIGINT UNSIGNED | 目标届次 `meet.id` |
| `target_meet_name` | VARCHAR(100) | 目标届次名称（冗余显示） |
| `copy_mode` | VARCHAR(32) | 复制方式：`STRUCTURE` 仅结构 / `FULL` 全量含人员 |
| `copy_scope_json` | JSON | 复制范围（组别、单位、项目、规则、裁判、岗位字典） |
| `is_clear_target` | TINYINT(1) | 复制前是否清空目标届次数据 |
| `total_count` | INT | 计划复制对象总数 |
| `success_count` | INT | 成功条数 |
| `fail_count` | INT | 失败条数 |
| `status` | VARCHAR(32) | 状态：`RUNNING` 进行中 / `SUCCESS` 成功 / `PARTIAL` 部分成功 / `FAILED` 失败 |
| `message` | VARCHAR(100) | 结果说明或失败原因 |
| `operator_id` | BIGINT UNSIGNED | 操作人 `sys_user.id` |
| `operator_name` | VARCHAR(50) | 操作人姓名（冗余显示） |
| `start_time` | DATETIME | 复制开始时间 |
| `end_time` | DATETIME | 复制结束时间 |
| `cost_ms` | INT | 耗时毫秒数 |

**索引与约束**：`IDX(target_meet_id)`、`IDX(source_meet_id)`、`IDX(create_time)`

## 第 6 节 赛前层

### calling 检录记录表
> 检录环节的逐人记录，衔接编排名单与成绩录入（未到即产生 DNS）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedule_id` | BIGINT UNSIGNED | 日程条目 `schedule.id` |

## 本层设计要点

1. **多届隔离与数据权限**：`meet` 为根实体，本层所有表均带 `meet_id`，查询由多租户插件自动拼接；`meet.status` 八态驱动报名、编排、成绩各模块的可用开关，归档后本层数据只读。领队账号经 `unit_staff`/`unit` 关联限定到本单位，裁判账号经 `referee` 关联限定到被分配日程。
2. **规则三层继承中本层的位置**：本层 `meet_rule_config` 是最上层「届次默认」，`meet.config_json` 作为同一层的扩展补充；下一层 `event_rule_config`（项目级）与再下一层 `event_round_rule`（轮次级）按需覆盖。取值优先级为「轮次级 > 项目级 > 届次默认」，本层只提供默认值与兜底，不承载单个项目的差异化设置。
3. **规则可配置全部落在字段上**：录取名次 `admit_rank`、每人限报项数 `athlete_max_events`、每单位每项限报 `max_per_unit`、兼项间隔 `conflict_interval_min`、接力双倍系数 `relay_double_factor`、破纪录是否计入团体分 `bonus_in_team_score`、奖牌榜排序 `medal_sort`、计时精度 `time_precision`、默认道次顺序 `default_lane_order_json`、风速上限 `wind_json`、田赛试跳次数 `field_attempt_count`、平局规则 `tie_break_json` 均为独立字段或 JSON，改规则不改代码。
4. **场地道数与道次顺序可配置**：`venue.lane_count` 区分 6 道与 8 道，`venue.lane_order_json` 保存该场地的优先道次顺序（默认 8 道 `[4,5,3,6,2,7,1,8]`），`meet_rule_config.default_lane_order_json` 提供届次兜底；编排取「场地配置优先、届次默认兜底」，同一届次不同场地可使用不同顺序。
5. **纪录多层级与现行判定**：`record.record_type` 覆盖世界、亚洲、全国、省、市、赛会、组别七个层级，配合 `group_code` 与 `gender` 区分组别纪录；`record_value` 用于成绩对标比较、`record_raw` 用于显示，`wind_speed`/`is_wind_legal` 标记风速合规性，`is_current` 区分现行纪录与历史纪录，避免历史数据参与对标。
6. **检录与成绩的衔接**：`calling` 以 `UK(heat_id, registration_id)` 唯一锁定每名参赛者在组内的检录状态，`PRESENT` 进入比赛，`ABSENT`/`WITHDRAW`/`DNS` 直接映射成绩层的无效成绩状态，做到「检录一次、成绩沿用」，无需重复录入。
7. **裁判分工支撑冲突检测**：`referee_assignment` 同时记录 `schedule_id`、`session_id`、岗位与 `start_time`/`end_time`，配合 `referee.max_duty_per_day`、`referee_duty.conflict_group` 与 `meet_rule_config.referee_interval_min`，可检测同一裁判时段重叠、超日限额、互斥岗位兼任三类冲突，并把结论回写 `conflict_flag`，与编排层 `conflict_log` 的 `REFEREE` 类型对应。
8. **赛前留痕与可追溯**：`draw_record` 保存抽签依据与结果快照，`start_list` 按版本发布并可撤回，`meet_clone_log` 记录复制范围与成败明细，三者共同保证赛前操作可解释、可回滚、可审计。
