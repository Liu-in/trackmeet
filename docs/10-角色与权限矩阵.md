# 角色与权限矩阵

> 权限模型：RBAC + 三层控制 —— **菜单权限**（页面可见）/ **按钮权限**（操作可用）/ **数据权限**（可见数据行范围）。
> 一个用户可绑定多个角色，权限取并集；`SUPER_ADMIN` 内置全量权限且不可删除。

## 1. 角色定义

| 编码 | 名称 | 定位 | 数据范围（`sys_role.data_scope`） | 默认角色 |
| --- | --- | --- | --- | --- |
| `SUPER_ADMIN` | 超级管理员 | 系统所有者：用户/角色/权限/字典/备份/日志 | `ALL` 全部届次与全部数据 | ✔ |
| `MEET_ADMIN` | 竞赛主管 | 一届运动会的负责人：规程、规则、审核、发布 | `MEET` 被授权届次的全部数据 | ✔ |
| `SCHEDULER` | 编排员 | 项目设置、自动编排、分组分道、日程调整 | `MEET` 届次内的报名与编排数据（成绩只读） | ✔ |
| `REGISTRAR` | 报名管理员 | 运动员建档、号码、报名与审核 | `MEET` 届次内的运动员与报名数据 | ✔ |
| `CHIEF_REFEREE` | 裁判长 | 成绩审核、判罚确认、纪录认定 | `MEET` 届次内全部成绩数据 | ✔ |
| `REFEREE` | 裁判 | 检录、成绩录入、田赛试跳试掷记录 | `MEET` 届次内**被分配的项目/单元**（`REF` 自定义范围） | ✔ |
| `ANNOUNCER` | 宣告员 / 记录员 | 成绩公告、大屏控制、证书生成 | `MEET` 届次内成绩只读 + 公告/证书写 | ✔ |
| `TEAM_LEADER` | 领队 / 教练 | 本单位报名、参赛名单、成绩查看 | `UNIT` 仅本单位数据 | ✔ |
| `ATHLETE` | 运动员（可选） | 查看个人项目、检录时间与成绩 | `SELF` 仅本人数据 | ✔ |
| `VIEWER` | 观众 / 大屏 | 公开成绩、公告、奖牌榜只读 | `PUBLIC` 仅公开数据 | ✔ |

> `REFEREE` 的数据范围实现方式：`referee_assignment` 中该用户对应的 `referee_id` → 关联的 `schedule_id` / `session_id` 集合，SQL 追加 `AND schedule_id IN (...)`。

## 4. 数据权限规则

| 角色 | 过滤维度 | 实现（服务端强制） |
| --- | --- | --- |
| SUPER_ADMIN | 无限制 | 不追加条件 |
| MEET_ADMIN | 届次 | `AND meet_id IN (授权届次集合)` |
| SCHEDULER | 届次 + 只读边界 | 编排/报名可写；成绩相关表强制只读（拦截写接口） |
| REGISTRAR | 届次 | 运动员/报名可写；其余只读 |
| CHIEF_REFEREE | 届次 + 成绩写 | `AND meet_id = ?`；成绩/纪录可写 |
| REFEREE | 被分配项目 | `AND schedule_id IN (SELECT schedule_id FROM referee_assignment WHERE referee_id = ? AND user_id = ?)` |
| ANNOUNCER | 届次 + 公告/证书写 | 成绩只读；`announcement`/`certificate` 可写 |
| TEAM_LEADER | 单位 | `AND unit_id = 当前用户绑定单位`（报名可写、审核不可见） |
| ATHLETE | 本人 | `AND athlete_id = 当前用户绑定运动员` |
| VIEWER | 公开 | 仅公开接口（`/api/screen/*`、`/api/announcements`、`/api/standings/medals`） |

**实现机制（三重防护，任一缺失即视为缺陷）**
1. **框架层**：MyBatis-Plus 多租户插件自动拼接 `meet_id`（`sys_*` 与全局字典表加入忽略列表）。
2. **注解层**：`@DataScope(unitAlias="u", userAlias="au")` 由 `DataScopeAspect` 依据角色追加 SQL 片段；Mapper XML 用 `${params.dataScope}` 占位。
3. **服务层**：写操作前校验目标对象 `meet_id` / `unit_id` 是否在调用者范围内，越权返回 `403`。

## 5. 权限落库映射

| 权限类型 | 表 | 关键字段 | 说明 |
| --- | --- | --- | --- |
| 菜单权限 | `sys_menu` / `sys_permission` | `menu_type=D/M`、`perm_code`、`path`、`component` | 前端据此生成动态路由与侧边菜单 |
| 按钮权限 | `sys_menu`(menu_type=B) / `sys_permission` | `perm_code='schedule:auto'` | 前端 `v-perm` 控制显隐，后端注解二次校验 |
| 接口权限 | `sys_permission` | `perm_type=API`、`api_path`、`http_method` | 与 `@PreAuthorize` 对应，便于审计接口暴露面 |
| 数据权限 | `sys_role` / `sys_role_dept`(可选) | `data_scope`、授权届次/单位明细 | 支持 `REF` 自定义范围（跨届次/跨单位授权） |
| 角色继承 | `sys_user_role` | 多角色并集 | 不做角色继承，避免权限推导复杂化 |

## 6. 关键权限边界（必须测试的越权场景）

| # | 场景 | 期望结果 |
| --- | --- | --- |
| 1 | 领队 A 通过修改 URL 参数查询领队 B 单位的运动员 | `403` 或返回空集（服务端强制 `unit_id`） |
| 2 | 编排员调用成绩审核接口 | `403`（`result:approve` 未授权） |
| 3 | 裁判查询未被分配的单元成绩明细 | 仅返回被分配项目 |
| 4 | 观众访问 `/api/system/users` | `403` |
| 5 | 用户通过请求头传入未授权的 `meetId` | `403`（校验届次授权集合） |
| 6 | 已审核成绩被裁判直接 PUT 修改 | `40001 成绩已审核锁定` |
| 7 | 领队访问其他单位的报名审核页 | 页面不可见 + 接口 `403` |
| 8 | 非 SUPER_ADMIN 触发数据恢复 | `403` |
