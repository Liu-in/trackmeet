## 2. 关键设计决策（ADR 摘要）

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| ADR-01 | 所有赛事业务表携带 `meet_id`，以「多届运动会」为第一隔离维度 | 支持多届运动会并存、跨届对比与归档；数据权限可下沉到 `meet_id` |
| ADR-02 | 全部田径规则以**数据 + 规则 JSON** 落地，禁止硬编码 | 要求 2；不同届次、不同组别、不同项目规则均可能不同 |
| ADR-03 | 规则分三层：`meet.config_json`（届次默认） → `event_rule_config`（项目级） → `event_round_rule`（轮次级） | 就近覆盖，避免规则爆炸；未配置则向上继承 |
| ADR-04 | 编排结果与编排输入分离：`schedule / heat / lane` 为可编辑结果表，编排引擎为无状态纯计算 + 落库 | 满足「自动编排后允许拖拽、修改、锁定、重新生成」 |
| ADR-05 | 锁定通过 `locked` 字段（`schedule.locked` / `heat.locked` / `lane.locked`）+ 重新生成时跳过 | 局部重排不破坏已确认的日程 |
| ADR-06 | 成绩录入采用「原始成绩 + 结构化成绩」双列（`result_raw` / `result_value` / `result_unit`） | 兼容手计时、电计时、田赛远度高度、全能单项分等异构数据 |
| ADR-07 | 积分与团体总分区分「明细表 `points`」与「快照表 `team_score`」 | 明细可追溯，快照支撑大屏与打印的高性能读取 |
| ADR-08 | 打印采用「专用 A4 打印视图（前端）+ 服务端 PDF/Excel/Word 双通道」 | 网页预览即时、服务端出正式秩序册与成绩册 |
| ADR-09 | 前端静态资源本地化（不依赖公网 CDN）、字体内嵌 | 局域网离线部署要求 |
| ADR-10 | 表名规避 MySQL 8 保留字：`group` → `meet_group`，系统表统一 `sys_` 前缀 | 兼容性与可读性 |

## 3. 术语表

| 术语 | 含义 |
| --- | --- |
| 届次 / meet | 一届运动会，如「XX 市第 12 届中学生田径运动会」 |
| 组别 / group | 运动员分组，如男子甲组、女子乙组、初中组 |
| 单位 / unit | 参赛单位（代表队），如「第一中学」 |
| 项目 / event | 竞赛项目，如「男子甲组 100 米」「女子乙组跳远」 |
| 轮次 / round | 项目的比赛阶段：及格赛、预赛、次赛、复赛、决赛 |
| 单元 / session | 竞赛单元，通常为某日上午/下午/晚上 |
| 日程 / schedule | 一条日程记录 = 某项目某轮次在某场地某时间的比赛安排 |
| 分组 / heat | 径赛的一组；田赛的一组出场顺序集合 |
| 道次 / lane | 径赛道次；田赛用 `field_order` 表示试跳/试掷顺序 |
| 兼项 | 同一运动员报名多个项目 |
| 递补 | 晋级时除各组前 N 名外，按剩余最好成绩补足名额 |
| 全能 | 十项全能/七项全能/五项全能等，按固定顺序比赛并查表得分 |
| DNS/DNF/DSQ/NM | 未出发/未完成/取消资格/无有效成绩 |
