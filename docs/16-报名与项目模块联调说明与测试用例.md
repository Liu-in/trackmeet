# 阶段 2 联调说明与测试用例（报名与项目管理模块）

> 覆盖范围：运动员 Excel 导入、报名管理/审核/限制校验、项目与轮次、规则配置（名次分表 / 晋级规则 / 破纪录加分 / 兼项间隔）。
> 对应后端：`backend/src/main/java/com/trackmeet/modules/{athlete,event}`；对应前端：`frontend/src/views/{athlete,registration,event}`。

---

## 一、环境与启动

### 1.1 Docker 全栈一键启动（推荐联调方式）

```bash
cd deploy
cp .env.example .env       # 按需修改 WEB_PORT / BACKEND_PORT / MYSQL_PORT / 口令
docker compose up -d --build
docker compose ps
```

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端（Nginx） | `http://localhost/`（默认 80，可用 `WEB_PORT` 改） | 静态站点 + `/api` 反向代理到后端容器（同源，无 CORS） |
| 后端 | `http://localhost:8080/actuator/health` | 健康检查 |
| MySQL | `localhost:3306` | 库 `trackmeet`，首次启动自动执行 `sql/01~06` |

默认账号：`admin / Admin@123`（首次启动由 `DefaultAccountInitializer` 用 BCrypt 写入；另有 `scheduler` / `referee` / `leader1` 演示账号，口令相同）。

### 1.2 本地开发（前后端分离）

```bash
# 终端 1：数据库 + 后端
cd deploy && docker compose up -d mysql
cd ../backend && ./mvnw spring-boot:run          # Windows: mvnw.cmd spring-boot:run

# 终端 2：前端（Vite dev server，代理 /api → localhost:8080）
cd frontend
npm install                                        # 或 pnpm install
npm run dev                                        # http://localhost:5173
```

前端代理配置见 [`frontend/vite.config.ts`](../frontend/vite.config.ts)（`VITE_PROXY_TARGET` 可覆盖后端地址）。

## 二、本模块接口总览

所有接口统一前缀 `/api`，统一返回 `{code,message,data,traceId,timestamp}`；`code=0` 成功。
除登录/验证码外均需请求头 `Authorization: Bearer <accessToken>`；业务接口建议携带 `X-Meet-Id: <届次ID>`（多租户拦截器据此追加 `meet_id` 条件）。

### 2.1 运动员与导入

| 方法 | 路径 | 权限编码 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/athletes` | `athlete:list` | 分页（keyword/unitId/groupId/gender/qualificationStatus/bibNo） |
| GET | `/api/athletes/{id}` | `athlete:query` | 详情 |
| POST | `/api/athletes` | `athlete:add` | 新增 |
| PUT | `/api/athletes/{id}` | `athlete:edit` | 修改 |
| DELETE | `/api/athletes/{id}` | `athlete:delete` | 逻辑删除（删除前改写号码唯一键） |
| GET | `/api/athletes/import-template` | `athlete:import` | 下载导入模板（xlsx，含「填写说明」Sheet） |
| POST | `/api/athletes/import` | `athlete:import` | 导入（multipart：`file`、`meetId`、`dryRun`） |

## 三、联调顺序（含 curl 示例）

```bash
BASE=http://localhost:8080/api

# ① 登录取令牌
TOKEN=$(curl -s -X POST $BASE/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')
AUTH="Authorization: Bearer $TOKEN"
MEET="X-Meet-Id: 1"

# ② 确认届次与基础数据（演示数据已含 4 组别 / 4 单位）
curl -s "$BASE/meets?page=1&size=10" -H "$AUTH"
curl -s "$BASE/meets/1/groups"        -H "$AUTH"
curl -s "$BASE/units?meetId=1"        -H "$AUTH" -H "$MEET"

# ③ 下载导入模板 → 填写 → 试运行校验 → 正式导入
curl -s -o 运动员导入模板.xlsx "$BASE/athletes/import-template" -H "$AUTH"
curl -s -X POST "$BASE/athletes/import?meetId=1&dryRun=true" -H "$AUTH" -F "file=@运动员导入模板.xlsx"
curl -s -X POST "$BASE/athletes/import?meetId=1"             -H "$AUTH" -F "file=@运动员导入模板.xlsx"

# ④ 批量生成标准项目（男子、高中组）
curl -s -X POST "$BASE/events/batch" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"meetId":1,"groupIds":[1],"gender":"MALE","templates":["100米","跳远","4×100米接力"]}'

# ⑤ 配规则：届次默认（兼项间隔 30 分钟）→ 项目级覆盖 → 轮次晋级规则
curl -s "$BASE/meets/1/rule-config" -H "$AUTH"
curl -s -X PUT "$BASE/meets/1/rule-config" -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"admitRank":8,"athleteMaxEvents":2,"maxPerUnit":3,"conflictIntervalMin":30,"relayDoubleFactor":2.00,
       "bonusInTeamScore":1,"medalSort":"GOLD_FIRST","timePrecision":"HUNDREDTH","fieldAttemptCount":3,
       "defaultLaneCount":8,"defaultLaneOrderJson":"[4,5,3,6,7,2,1,8]"}'
curl -s -X PUT "$BASE/events/1/rule-config" -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"admitRank":8,"conflictIntervalMin":20,"laneOrderJson":"[4,5,3,6,2,7,1,8]","windJson":"{\"applicable\":true,\"maxLegal\":2.0}"}'

# ⑥ 报名校验（不落库）→ 正式报名 → 审核
curl -s -X POST "$BASE/registrations/check" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"meetId":1,"items":[{"eventId":1,"unitId":1,"athleteId":1,"isRelay":0}]}'
curl -s -X POST "$BASE/registrations/batch" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '{"meetId":1,"unitId":1,"eventId":1,"athleteIds":[1,2,3]}'
curl -s -X POST "$BASE/registrations/approve" -H "$AUTH" -d '{"ids":[1,2,3]}' -H 'Content-Type: application/json'

# ⑦ 统计、预警、锁定
curl -s "$BASE/registrations/statistics?meetId=1&dimension=EVENT" -H "$AUTH" -H "$MEET"
curl -s "$BASE/registrations/warnings?meetId=1"                     -H "$AUTH" -H "$MEET"
curl -s -X POST "$BASE/registrations/lock" -H "$AUTH" -H 'Content-Type: application/json' -d '{"meetId":1}'

# ⑧ 名次分表与加分规则
curl -s "$BASE/score-rules?page=1&size=10&meetId=1" -H "$AUTH" -H "$MEET"
curl -s -X PUT "$BASE/score-rules/1/items" -H "$AUTH" -H "$MEET" -H 'Content-Type: application/json' \
  -d '[{"rankNo":1,"rankLabel":"第一名","pointValue":9,"tiePolicy":"AVERAGE","isTeamScore":1},
       {"rankNo":2,"rankLabel":"第二名","pointValue":7,"tiePolicy":"AVERAGE","isTeamScore":1}]'
curl -s "$BASE/bonus-rules?page=1&size=10&meetId=1" -H "$AUTH" -H "$MEET"
```

## 四、关键字段契约（前后端一致性基线）

### 4.1 运动员导入模板（14 列，表头不可修改）

| 列 | 必填 | 校验规则 |
| --- | --- | --- |
| 姓名* | 是 | 非空、≤ 50 |
| 性别*（男/女） | 是 | 男/女/MALE/FEMALE |
| 出生日期*（yyyy-MM-dd） | 是 | `yyyy-MM-dd`、`yyyy/M/d`、`yyyyMMdd` 均可解析 |
| 身份证号* | 是 | 非空、≤ 32、届次内唯一 |
| 单位编码* | 是 | 必须存在于该届次（也支持填单位名称） |
| 组别编码* | 是 | 必须存在于该届次（也支持填组别名称） |
| 号码（留空自动生成） | 否 | ≤ 32、届次内唯一；留空按「单位前缀-序号」生成 |
| 班级 / 联系电话 / 监护人 / 监护人电话 | 否 | 长度限制（64 / 32 / 50 / 32） |
| 资格状态 | 否 | 待审/合格/不合格/禁赛，留空默认「合格」 |
| 是否仅参加接力 | 否 | 是/否，留空默认「否」 |
| 备注 | 否 | ≤ 100 |

导入返回：`totalCount / successCount / failCount / autoBibCount / taskId / message / errors[] / errorFileBase64`。
`dryRun=true` 仅校验不落库；`errors` 最多返回 200 条，完整明细在 `errorFileBase64`（前端可一键下载）。

### 4.2 报名请求体

```json
{
  "meetId": 1, "eventId": 1, "unitId": 1, "groupId": 1,
  "athleteId": 1, "isRelay": 0,
  "relayName": null, "relayTeamSeq": null,
  "seedResult": "11\"23", "seedValue": 11.23, "seedUnit": "s", "seedSource": "PB",
  "remark": null,
  "members": [{ "athleteId": 4, "legNo": 1 }]
}
```

### 4.3 规则字段（三层继承）

| 规则 | 届次级字段 | 项目级字段 | 轮次级字段 |
| --- | --- | --- | --- |
| 录取名次 | `admitRank` | `admitRank` | `admitRank` |
| 晋级 | – | – | `groupTopN`/`bestLoserCount`/`targetCount`/`advanceJson` |
| 兼项间隔 | `conflictIntervalMin` | `conflictIntervalMin` | – |
| 道次顺序 | `defaultLaneOrderJson` | `laneOrderJson` | – |
| 风速 | `windJson` | `windJson` | – |
| 试跳次数 | `fieldAttemptCount` | `attemptCount` | – |
| 名次分表 | `scoreRuleId` | – | – |
| 破纪录加分 | `bonusInTeamScore`（是否计入团体分） | – | – |
| 接力双倍 | `relayDoubleFactor` | – | – |

读取优先级：**轮次级 > 项目级 > 届次级 > 系统兜底默认**；项目级规则接口返回每个字段的 `xxxSource`（`PROJECT`/`MEET`/`DEFAULT`），前端以标签显示来源，「恢复继承」即删除项目级行。

## 五、报名限制校验规则与错误码

| # | 规则 | 触发条件 | 错误码 |
| --- | --- | --- | --- |
| 1 | 报名期校验 | 届次状态 ≠ `REG_OPEN` | 20002 报名已截止 |
| 2 | 资格校验 | 运动员不存在 / 非同届次 / 资格非 `QUALIFIED` | 20003 / 400 参数 |
| 3 | 组别与性别 | `event.group_id` ≠ `athlete.group_id`，或性别不符（MIXED 不限） | 20003 |
| 4 | 重复报名 | 同届次 + 同项目 + 同运动员已有非取消记录 | 20004 重复报名 |
| 5 | 每人限报项数 | 个人项数 > `athleteMaxEvents`；接力项数 > `relayMaxPerAthlete` | 20003 |
| 6 | 每单位每项限报 | 该单位该项目报名数 ≥ `max_per_unit`（项目级优先） | 20003 |
| 7 | 接力人数 | 队员数不在 `relay_min ~ relay_max`；同项目同人重复 | 20003 |
| 8 | 年龄区间 | 出生日期超出组别 `birth_date_start/end` | WARN（不阻断，写入校验项） |

> 校验项结构：`{rowIndex, athleteId, athleteName, eventId, eventName, level(ERROR/WARN), code, message}`；`ERROR` 存在即拒绝落库，`WARN` 仅提示。

## 六、测试用例

> 前置：已执行 `sql/01~06`；使用 `admin` 令牌；`X-Meet-Id: 1`；演示数据含 4 组别、4 单位、16 运动员（其中 2 人为 `PENDING` 资格）、2 套名次分方案、3 条加分规则。

### 6.1 运动员导入（TC-IMP）

| 用例 | 步骤 | 预期结果 |
| --- | --- | --- |
| TC-IMP-001 | 下载模板 | 返回 xlsx，含「运动员导入模板」「填写说明」两个 Sheet，表头 14 列，示例 2 行 |

| TC-IMP-005 | 姓名留空 | 该行失败，错误原因含「姓名不能为空」，其余行成功，`status=PARTIAL` |

## 八、常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 列表返回 401 | 未携带 `Authorization`，或口令修改后令牌版本失效（需重新登录） |
| 列表能查到其他届次数据 | 未传 `X-Meet-Id`；多租户拦截器在无届次上下文时不追加条件（联调务必带该头） |
| 导入报「Excel 解析失败」 | 使用了旧模板或改动了表头；请重新下载模板 |
| 导入全部失败且原因相同 | 单位/组别编码与「单位管理/组别管理」不一致（可用单位名称/组别名称替代） |
| 报名提示超出限制 | 规则来源为届次默认或项目级，检查 `meet_rule_config.max_per_unit` 与 `event.max_per_unit` |
| 项目级规则保存后不生效 | 检查字段是否为空（空字段按「非空更新」跳过），或该字段被轮次级规则覆盖 |
| 前端页面空白 | 该菜单的 `sys_menu.component` 对应的 vue 文件不存在 → 回退占位页；确认文件路径大小写一致 |
| 前端 404（刷新后） | Nginx 未配置 history 回退：`try_files $uri $uri/ /index.html`（见 `deploy/nginx/default.conf`） |
