# 系统层字段清单

> 通用字段见 [字段清单总览](12-00-字段清单总览.md)，下表仅列业务字段。
> 本层 16 张表为**全局表**（RBAC、字典、日志、配置、文件、备份），不含 `meet_id` 租户隔离列；届次相关语义通过业务列弱引用表达。
> 枚举字段一律存英文码，显示名从字典或前端映射取；类型遵循总览第 1 节。

---

### sys_user 用户表
> 系统登录账号，承载部门/单位归属、密码策略与登录状态。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `username` | VARCHAR(64) | 登录名，全局唯一 |
| `password` | VARCHAR(100) | BCrypt 密文，禁止存明文 |
| `real_name` | VARCHAR(50) | 真实姓名 |
| `phone` | VARCHAR(20) | 手机号，可用于登录与找回 |
| `email` | VARCHAR(100) | 邮箱，用于找回密码 |
| `avatar_file_id` | BIGINT UNSIGNED | 头像文件 `sys_file.id` |
| `dept_id` | BIGINT UNSIGNED | 所属部门 `sys_dept.id` |
| `unit_id` | BIGINT UNSIGNED | 关联参赛单位 `unit.id` |
| `status` | VARCHAR(32) | ENABLED 启用 / DISABLED 停用 |
| `is_builtin` | TINYINT(1) | 1 内置账号，禁止删除 |
| `pwd_update_time` | DATETIME | 密码最后修改时间 |
| `pwd_error_count` | INT | 连续输错次数，达阈值锁定 |
| `lock_until` | DATETIME | 锁定到期时间，空为未锁 |
| `force_pwd_change` | TINYINT(1) | 1 首次登录强制改密 |
| `token_version` | INT | 令牌版本，自增即失效旧令牌 |
| `last_login_time` | DATETIME | 最后登录时间 |
| `last_login_ip` | VARCHAR(64) | 最后登录 IP |
| `sort_no` | INT | 列表显示顺序 |
| `remark` | VARCHAR(255) | 备注 |

**索引与约束**：`PK(id)`、`UK(username)`、`IDX(dept_id)`、`IDX(unit_id)`、`IDX(status)`

### sys_role 角色表
> 权限与数据范围的集合，通过用户-角色、角色-权限两级关联授权。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `role_code` | VARCHAR(64) | 角色编码，唯一，如 SCHEDULER |
| `role_name` | VARCHAR(100) | 角色名称 |
| `data_scope` | VARCHAR(32) | 数据范围：ALL 全部 / MEET 本届次 / UNIT 本单位 / SELF 本人 / REF 自定义 |
| `data_scope_json` | JSON | REF 时的部门/单位/届次 ID 集合 |
| `status` | VARCHAR(32) | ENABLED 启用 / DISABLED 停用 |
| `is_builtin` | TINYINT(1) | 1 内置角色，禁止删除 |
| `sort_no` | INT | 列表显示顺序 |
| `remark` | VARCHAR(255) | 备注 |

**索引与约束**：`PK(id)`、`UK(role_code)`、`IDX(data_scope, status)`

### sys_permission 权限表
> 统一的权限点定义，区分菜单权限、按钮权限与接口权限。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `perm_code` | VARCHAR(64) | 权限编码，唯一，如 schedule:auto |
| `perm_name` | VARCHAR(100) | 权限名称 |

| `module` | VARCHAR(64) | 所属模块，用于日志归类 |
| `api_path` | VARCHAR(200) | 接口路径（Ant 风格），API 用 |
| `http_method` | VARCHAR(16) | GET/POST/PUT/DELETE，API 用 |
| `api_group` | VARCHAR(64) | 接口分组，如 REGISTRATION |
| `is_builtin` | TINYINT(1) | 1 内置权限，禁止删除 |
| `status` | VARCHAR(32) | ENABLED 启用 / DISABLED 停用 |
| `sort_no` | INT | 列表显示顺序 |
| `remark` | VARCHAR(255) | 备注 |

**索引与约束**：`PK(id)`、`UK(perm_code)`、`IDX(perm_type, status)`、`IDX(menu_id)`、`IDX(api_path, http_method)`

| `visible` | TINYINT(1) | 1 导航可见，0 隐藏 |
| `keep_alive` | TINYINT(1) | 1 页面缓存 |

> 全局写操作审计流水，含修改前后值快照，用于追责与回溯。

| `action` | VARCHAR(64) | 动作码，如 AUDIT、PUBLISH |

| `target_type` | VARCHAR(64) | 目标类型，如 result |

| `before_json` | JSON | 修改前值快照，仅存变更字段 |

| `params_summary` | VARCHAR(500) | 请求参数摘要，敏感字段脱敏 |
| `request_id` | VARCHAR(64) | 请求链路 ID，用于串联多表操作 |
| `ip` | VARCHAR(64) | 客户端 IP |
| `ip_region` | VARCHAR(100) | IP 归属地 |
| `ua` | VARCHAR(500) | User-Agent 原文 |
| `os` | VARCHAR(64) | 操作系统 |
| `browser` | VARCHAR(64) | 浏览器 |

| `result` | VARCHAR(32) | SUCCESS 成功 / FAIL 失败 |
| `error_msg` | TEXT | 失败异常摘要 |
| `operate_time` | DATETIME | 操作发生时间，分区与清理依据 |
| `is_archived` | TINYINT(1) | 1 已归档，可被清理任务删除 |

**索引与约束**：`PK(id)`、`IDX(operate_time)`、`IDX(user_id, operate_time)`、`IDX(module, action)`、`IDX(target_type, target_id)`、`IDX(request_id)`

**索引与约束**：`PK(id)`、`IDX(meet_ref_id, report_type)`、`IDX(operator_id, print_time)`、`IDX(print_time)`

---

## 本层设计要点

1. **RBAC 三层控制在表结构上的落点**：`sys_menu` 负责导航树与可见性（`menu_type` D/M/B），`sys_permission` 用 `perm_type` 区分 MENU/BUTTON/API 三类权限点，`sys_role_permission` 承载实际授权。前端按钮指令校验 `perm_code`，后端以 `api_path + http_method` 拦截接口，菜单树仅渲染 `visible=1 且 status=ENABLED` 的节点，从而实现「菜单权限 + 按钮权限」双层收敛。
2. **数据权限靠 `data_scope` 而非新增表**：`sys_role.data_scope` 五档（ALL/MEET/UNIT/SELF/REF）覆盖绝大多数场景，仅 REF 需要 `data_scope_json` 存自定义部门/单位/届次集合。行级过滤在 MyBatis-Plus 拦截器中统一追加条件（本单位、本人、被分配项目），届次隔离由业务表的 `meet_id` 完成，系统表保持全局。
3. **菜单与权限的冗余设计**：`sys_menu.perm_code` 与 `sys_permission.perm_code` 值域一致，菜单渲染与按钮显隐直接读菜单行，不必每次联表；`sys_role_permission.menu_id` 与 `perm_type` 为冗余列，用于按菜单树快速统计授权覆盖率，写时由服务层保证一致。
4. **逻辑删除与唯一约束的冲突处理**：`username`、`role_code`、`perm_code`、`dict_type`、`config_key` 等业务唯一键**不把 `deleted` 并入唯一索引**，而采用「删除时改写唯一键」策略（追加 `_d{id}` 后缀），既保持唯一索引紧凑，又允许同一编码在删除后重新启用；关联表则直接以 `UK(role_id, permission_id)`、`UK(user_id, role_id)` 物理删除重授权，不做逻辑删除。
5. **密码与令牌策略**：库内只存 BCrypt 密文，不存明文与可逆密文；`pwd_error_count` 达阈值即写 `lock_until` 做短时锁定，`force_pwd_change` 支持首登与重置后强制改密。`token_version` 配合 JWT：改密、停用、角色或数据范围变更时自增，已签发令牌立即失效，无需服务端会话表。
6. **日志表的分区与清理策略**：`sys_operation_log`、`sys_login_log` 只追加不更新，索引以 `operate_time`/`login_time` 为首列，预留按月 RANGE 分区；`is_archived` 标记后由定时任务按月归档并删除超期数据。`before_json`/`after_json`/`params_summary` 只存变更字段与脱敏摘要，控制单行体积，避免大 JSON 拖慢审计查询。
7. **备份、文件与导入导出的一体化**：`sys_backup_record` 只登记路径、大小、md5 与状态，恢复动作写 `restore_by`/`restore_time` 并同步落 `sys_operation_log`；`sys_file` 以 `UK(md5, file_name)` 实现秒传去重、`ref_count` 支持回收；`sys_import_task` 用 `task_direction` 同时承载导入与导出，失败明细经 `error_file_id` 指向 `sys_file`，保证「谁导入、导了多少、错在哪」可追溯。
8. **打印留痕的届次维度处理**：*数据表清单*中 `sys_print_log` 的 `meet_id` 属届次**引用**而非租户隔离列，本清单按「系统表不含 `meet_id`」统一改为 `meet_ref_id` 弱引用，既可满足按届次筛选与重打，又不破坏系统层全局表的定位；`params_json` 保存打印参数快照，`print_count` 支撑补打审计。
